# Data/Scripts/RTS_Functions
- **Role:** This folder holds the reusable Lua libraries and engine-core scripts that drive the RTS game behaviour, including AI logic, combat and movement tasks, camera and keyboard controls, collision handling, vehicle and weapon configuration, and A* pathfinding utilities. It supports the RTS level setup and gameplay by providing shared functions that game objects and scripts call.
- **Entry point:** RTS_Init.lua
- **Files:** RTS_AI.lua - library implementing RTS AI behaviour, shared AI settings, sense handling, task execution, combat and animation logic, and top-level AI entry points; RTS_Attributes.lua - library defining two reusable functions for initializing game objects and running a final pass over registered game objects to configure attributes; RTS_Behaviours.lua - library defining reusable behaviour functions for fleeing, walking, combat, zombie, vehicle, and follow-player logic for game objects; RTS_Camera.lua - library implementing RTS camera update logic handling zoom, look-around, rotation, and camera/light position updates driven by input keys and game state; RTS_Collisions.lua - library containing collision-handling logic for object-to-object collisions, damage application, vehicle driving state changes, door opening, fight orders, and untangle events; RTS_Events.lua - library defining event task helpers for the RTS game including stunned, finish, untangle, kickhead, waitforhitbad, and hit events, plus hitbad event task scheduling and sound playback; RTS_Game.lua - engine-core core game script handling mouse click and selection logic, the RTS game loop, camera and light tracking, and keyboard-driven time and camera controls; RTS_Init.lua - level-script loading the RTS multi-folder level setup by preloading script libraries, initializing game object variables, assigning entity behaviors, configuring scene, light, and shadow settings, and preparing the A* grid; RTS_Keyboard.lua - library providing keyboard-driven controls including time and light manipulation functions, a helper for selecting tracked objects for the team-select screen, a shared global flag, and key-handling routines adjusting game speed, scene speed, and tracked light properties; RTS_Orders.lua - library defining combat and movement task helpers for enemy objects covering order-based movement, vehicle driving, eating, gun pickup, and path-based actions; RTS_Senses.lua - library providing sensor and memory logic handling distance table construction, eye and ear line-of-sight detection, and object sensing state management; RTS_Sounds.lua - library configuring scene sound damping parameters and a global sound emitter counter at load, and providing functions for assigning free sound emitters and setting up zombie voice sound emitters; RTS_Tasks.lua - library defining shared rotation and turn-control functions letting objects be rotated toward or away from other objects or spots; RTS_Utilities.lua - library containing reusable utility functions including text box creation, console output helpers, object selection and highlighting utilities, selection rectangle configuration, house destruction and ragdoll setup, game end condition checks, and collision reset helpers; RTS_Vehicles.lua - engine-core containing core vehicle control and sound configuration logic including engine pitch and sound handling, steering and driving routines, and vehicle state tracking; RTS_Weapons.lua - library containing utility functions for weapons including helpers to attach guns and two-handed weapons to carrier objects, checking friendly object collisions, finding friendly objects in an area, and configuring right-handed pistol and melee weapon behavior across the shared object list; RTS_astar.lua - library implementing A* pathfinding and node grid utilities defining SimpleList and SimpleMinHeap data structures, A* search and node expansion functions, grid lookup helpers, path generation routines, and setup helpers for building the pathfinding grid.
- **Shared with other folders:** This folder takes from the engine's shared globals and folders such as `Data/` (e.g. `gameroot`, `gObjects`), `loadLevel`, `make`, `get`, `getObjectInfo`, `setObjectInfo`, and `dofile` for loading scripts and accessing objects. It shares its RTS-specific libraries and functions with the RTS level folders, including the `RTS_Entities` sub-folder, which depends on these scripts for entity behaviour and game logic.
- **Procedure candidates:** RTS_AI.lua - generates procedural paths and animation parameters via `try_to_reach_object` (A* path generation and trimming based on source/target distance) and `do_task`/other functions computing animation tables, movement values, and object orientation from task types, object state, and numeric parameters using `math.ceil`, `math.random`, `math.max`, and `math.floor`; RTS_Behaviours.lua - generates object task paths and behaviour state procedurally using A* path generation, distance checks, and random selection rules via `randomWalking`, `walk_between_safe_places`, and `follow_player`; RTS_astar.lua - `createNodeGrid`, `generateAStarPathBetweenPositions`, and `setupAStarGrid` generate or configure node grids, pathfinding layouts, and A* grid setups from numeric rules and mesh bounds rather than loading a fixed asset file.
- **Glossary:**
  - A* pathfinding - pathfinding system using node grids, search, and node expansion to generate paths between object positions.
  - AI behaviour - logic that drives game object behaviour, including sense handling, task execution, combat, and animation.
  - Game object - a registered entity in the engine that can have attributes, behaviours, and properties configured via engine calls.
  - Level script - script that loads and initializes a multi-folder game level setup, including preloading libraries and configuring scene settings.
  - Object sense handling - logic that detects objects within sensor ranges and manages object sensing state for game objects.
  - Vehicle control - logic for updating vehicle behavior, sounds, and physics state across the game.
  - A* grid setup - setup of the pathfinding grid used by the A* system for path generation.
- **Verdict:** keep - The folder contains the core reusable libraries and engine-core scripts required to drive the RTS game behaviour, with clear separation of AI, combat, camera, collision, vehicle, weapon, and pathfinding logic, and an entry point that initializes the level setup. It provides shared functions that the RTS level folders and entities depend on, so it should be retained for porting to a new engine.
